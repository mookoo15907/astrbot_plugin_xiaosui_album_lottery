# 小碎相册抽签 v0.1.1

这是一个独立的 AstrBot 插件。群友仍在 QQ 群相册的报名图片下留言，管理员让小碎读取、按时间筛选、按 QQ 去重，检查名单后再抽取。

**v0.1.0 已由用户安装，帮助指令显示正常；v0.1.1 修复相册编码 ID 含特殊字符时被误判为「相册编号异常」的问题。离线测试通过，修复版仍需在测试群验证真实相册读取。** 现有小碎插件及 `xiaosui_state.json` 没有修改。

## 报名规则

- 只统计上传动态里的直接留言；留言下面的回复、回复的回复均不入池，正文不影响报名。
- 北京时间，精确到秒。开始秒也可报名，即 `留言时间 >= 开始时间`。
- 开始时间之前的主办方留言忽略；开始时间起，主办方最早的一条直接留言确定截止秒。主办方永远不入池。
- 截止秒之前的直接留言有效；截止秒之后无效。与截止留言同秒的新 QQ 需要管理员在 QQ 中核对先后并明确纳入或排除，插件不会猜顺序。
- 同一个 QQ 只保留有效窗口内最早的留言。窗口前的旧留言不会挡住窗口内的新报名。
- 抽取不放回。同一池只产生一份结果；重复指令、重启后再发指令均返回原结果。不会自动补抽或重抽。

读取接口针对**上传批次/上传动态**，不是根据照片页面的评论计数器。请为每轮报名**单独上传一张图片**，避免同一批上传多张照片共享动态造成范围混淆。图片上传时间、批次和主办方 QQ 会在建池后展示，务必核对。

## 最短操作示例

在报名群里，由 AstrBot 管理员发送以下指令。若你的机器人要求唤醒前缀，请加 `/` 或先 @ 小碎。这里的编号是插件本次列出的编号，不是 QQ 的内部编号。

```text
相册抽签 相册
相册抽签 图片 1
相册抽签 建池 1 2026-10-04T22:10:00
```

第三条表示：选择图片列表中的第 1 张，报名从 2026 年 10 月 4 日 22:10:00 开始，主办方默认是发指令的人。若组织者不是指令发送人，可在最后加其 QQ：

```text
相册抽签 建池 1 2026-10-04T22:10:00 你的主办方QQ
```

群友留言后，主办方在同一张报名图对应的动态下发表截止**直接留言**，再发送：

```text
相册抽签 统计
相册抽签 名单
相册抽签 确认
相册抽签 抽取 1
```

`抽取 1` 抽一个 QQ；改成其他正整数可抽多人，不能超过有效人数。先保存结果，再公布 QQ。

如果显示截止同秒待核对，先处理所有待核对留言，再确认：

```text
相册抽签 边界
相册抽签 边界 留言编号 纳入
相册抽签 边界 另一个留言编号 排除
相册抽签 名单
相册抽签 确认
```

`边界` 列表显示留言编号和 QQ；编号必须来自当前快照。重新统计会清除旧快照和同秒决定。确认后锁定名单，不再允许刷新或改边界。

## 其他指令

| 指令 | 用途 |
| --- | --- |
| `相册抽签 帮助` | 查看指令说明 |
| `相册抽签 状态` | 查看本群活动池、时间、主办方和已抽结果 |
| `相册抽签 名单 2` | 查看去重名单第 2 页，每页 20 人 |
| `相册抽签 边界 2` | 查看同秒核对列表第 2 页 |
| `相册抽签 相册 2` | 查看当前这批相册的第 2 页 |
| `相册抽签 相册 下一页` | 从 QQ 取得下一批相册；编号会重新开始 |
| `相册抽签 图片 1 2` | 查看相册 1 当前这批图片的第 2 页 |
| `相册抽签 图片 1 下一页` | 从 QQ 取得相册 1 的下一批图片；编号重新开始 |
| `相册抽签 结束 池编号` | 结束当前活动，保留历史，才能再建新池 |
| `相册抽签 记录 池编号` | 查看本群这个历史池的概要和结果 |

选择列表分机器人、群和管理员隔离，10 分钟有效。活动池分机器人和群隔离；只有 AstrBot 管理员可以操作。**QQ 群管理员身份本身不等于 AstrBot 管理员**，管理员需在 AstrBot 后台配置。任何 AstrBot 管理员都能管理本群活动。

结束后新建池属于一轮明确的新抽签，可能抽到往期参与者；不能将它当作原池重复指令。插件不决定你的中奖资格或跨活动排除规则。

## 读取不完整时

每页 20 条，完整读取两遍，比较全部直接留言的编号、QQ 和时间。允许 QQ 在最后空页返回 `total=0`，但必须收集到非空页所报告的全部条数，且编号唯一。重复页、缺页、总数变化、两遍元数据不同、缺失关键字段、未找到截止留言时停止统计，不保存可抽取的不完整名单。默认最多 2000 条直接留言、读取总时限三分钟。

QQ 并没有提供这里可用的事务快照；两遍一致是校验措施，不能证明服务端从未隐藏或延迟某条留言。请在活动结束、留言稳定后统计，并核对名单。老图可能存在 QQ 多个入口计数不一致，插件不会拿照片计数器作为报名总数。

统计前会撤销原有未确认预览。重新统计失败后，旧预览也不能确认或抽取。已确认名单不会再刷新。QQ 接口变化时会提示停止，由管理员检查适配，不会自动换读取渠道或绕过校验。

## 安装和数据

需要 AstrBot 的 OneBot v11 平台已连接 NapCat，机器人已登录并在目标群中。插件通过已有连接使用 `get_qun_album_list`、`get_group_album_media_list`、`get_credentials`，不需要新增 HTTP/WS 入口或填写 NapCat WebUI 令牌。Python 3.10+，除 AstrBot 自身外没有额外依赖。

仓库地址：<https://github.com/mookoo15907/astrbot_plugin_xiaosui_album_lottery>。在 AstrBot 后台的插件管理中选择通过仓库链接安装，填写这个地址。加载后，由 AstrBot 管理员在测试群发送「相册抽签 帮助」。

手动安装：将本目录放入 `AstrBot/data/plugins/astrbot_plugin_xiaosui_album_lottery/`，然后在 AstrBot 后台加载此插件。安装包也可供支持 ZIP 安装的 AstrBot 后台使用。加载成功后先在测试群验证下面的清单，再用于正式抽签。

数据目录采用 AstrBot 的插件数据工具；旧版本缺少此工具时，只在标准 `data/plugins/插件名` 安装结构下使用同级目录：

```text
AstrBot/data/plugin_data/astrbot_plugin_xiaosui_album_lottery/lottery_state.json
```

应将这个文件纳入后续备份；它包含池配置、QQ/留言编号/时间的快照、同秒核对记录、抽取结果和操作记录。不会写入 Cookie、登录令牌、照片 URL 或留言正文。QQ 返回的原始响应可能含正文，但插件不使用、不保存。只有读取时临时取得网页登录态，访问固定 QQ HTTPS 地址，不跟随重定向，不修改相册或评论。

更新插件时保留 `plugin_data`。停用或移除这个独立插件不会修改 `astrbot_plugin_ceshi/data/xiaosui_state.json`。

## 本机验证与部署前验证

在本机项目根目录执行：

```text
python -m unittest discover -s astrbot_plugin_xiaosui_album_lottery/tests -v
```

测试覆盖报名窗口、截止留言、回复排除、有效窗口内去重、同秒处理、27+3/122 条分页模拟、缺页和变动拒绝、原子保存、重复抽取和重启、权限及群/机器人隔离。使用临时目录、假登录态及本机 HTTP 服务；**这些不是对真实 QQ 的再次验证**。AstrBot 的指令测试使用最小框架替身，不等于真实框架加载测试。

部署前在测试群检查：

1. 插件真正加载，管理员能看到相册与正确上传时间，普通群友无法使用抽签指令。
2. 选用独立上传的测试图，设置开始时间，加入直接留言、重复 QQ、回复，以及开始前的主办方留言。
3. 主办方发截止直接留言，核对 QQ 页面与插件名单；跨页数据也要检查。
4. 如有同秒留言，确认前逐条处理；确认后抽取多人，保证 QQ 不重复。
5. 重复抽取并重启插件后查看原结果，验证没有重抽；确认备份文件路径。
